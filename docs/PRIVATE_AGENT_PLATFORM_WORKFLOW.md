# 本地 Agent 平台：数据、标注与模型的工作流程

本说明针对当前源码工作台，不表示以前下载的 Windows 安装器已自动更新。项目内的真实业务数据仍在本机；本地 HTTP 上传与“向第三方模型外发原图”是两件事。不要将配置存在、任务执行完成、模型训练完成或数据检查通过混为一个 PASS。

## 先区分两个“好坏”

| 判断对象 | 例子 | 应如何处理 |
| --- | --- | --- |
| 产品是否有缺陷 | 齿轮有缺口，图片清晰且框正确 | 可以是很有价值的缺陷训练样本，不应因为产品 NG 就扔掉 |
| 数据是否可用 | 虚焦、跨集合重复、标注错误、来源或审核证据不足 | 根据问题返修、补证或隔离，不能直接进入训练 |

数据池记录的是指定检查合同下的可用性。成员分为合格候选、需要返修、证据不足；“没有报错”不等于已证明标注正确。保留正常与缺陷样本的业务类别，并另行记录数据审核去向。

## 1. 进入自己的平台

启动现有源码工作台后，首次使用需要创建首个本地管理员账户。其他用户注册后等待管理员批准；批准不会自动加入现有工作区。已启用用户可以在账户页显式新建自己的工作区，或由已有工作区的所有者加入成员。

入口：账户与团队 `/account`，Agent 平台 `/platform`。登录会话保存在浏览器内存，刷新或重开可能需要重新登录。账户状态、工作区成员资格与原始数据授权分别验证；平台管理员不因此拥有所有项目的数据访问权。

这是本地账户系统，不是企业 SSO、MFA 或公网多租户认证的认证结论。

## 2. 分开配置语言模型与视觉模型

入口：模型与 API 管理 `/models`。

- **Agent 语言模型 / API**：本机 Ollama 或明确选择的外部服务。填写实际已经存在的模型 ID，显式测试连接，再保存本账户、本工作区配置。不会因为打开页面就下载模型或测试外部服务；默认模型变更也需要明确选择。Windows 外部密钥使用服务端 DPAPI，不放进网页变量、浏览器持久存储或回执。
- **视觉模型与训练**：`/models?tab=vision`。分别登记可信本地权重、外部 Python 运行环境及已审核的检测数据集。登记权重只核对文件与摘要，不代表已加载或已验证效果。运行环境探测和训练都需要单独授权。

当前检测训练支持已安装架构的随机初始化，以及用户明确授权的已登记权重初始化。随机初始化不能称为“预训练模型”。YOLO26n 是否可执行以实际运行环境探测为准，不自动下载权重、不静默安装训练依赖。Ultralytics 的适用许可证与 `.pt` 反序列化风险需要明确确认。

## 3. 标注、冻结，再检查

入口：图像工作簿 `/workspace` → 工作概览 `/command-center`。

导入自己的图片，保存真实框、类别、每个样本的 train/val/test 用途、审核要求及具名审核。正常空框样本须明确声明正常，不能靠“没有框”自动推断。冻结时，服务端重新读取图片和标注版本；浏览器表单里的数值不能替代真实来源。

冻结后创建检查任务，查看并批准计划。专业工具负责图像、重复、标注、覆盖与治理检查；Agent 组织任务和证据，Worker 在合同内补证。工具失败、证据缺失或来源变化时停在 HOLD，不显示伪诊断或虚构置信度。

## 4. 逐成员审核与返修循环

入口：数据池与返修版本 `/data-pools`，选择已完成的来源任务。

逐项查看真实 finding、用途、图片与标注摘要，明确选择：

- 合格候选：当前证据下允许进入派生候选，仍不是训练批准或标签真值证明。
- 需要返修：记录服务端问题代码、重标/重采/去重或重新分组动作、处理说明与结果状态。
- 证据不足：保持 HOLD，补证或调查，不用默认合格消除缺失信息。

原始快照和旧审核版本不覆盖。修改工作副本后，需要新快照、新任务、新 Gate 和新审核版本；不能只把旧记录的状态改成“已修好”。只选合格子集时，新来源仍须独立检查；全部成员合格时引用已有完整快照，不复制一份假“新数据”。

批次因其他成员的已定位问题未通过时，当前成员只有同时满足以下条件才可成为干净补集候选：投影 VERIFIED、本成员无 finding、至少另一成员有已映射 finding、无 global/unmapped/工具失败或缺证问题、preflight 为 HOLD，且唯一 blocker 为 `GATE_NOT_PASS`。这仍只是派生候选，派生后须新 Gate PASS。

返修复验完成后，在**同一个数据池**保留池选择，把“来源任务”切换为返修后的新 Task，对新 Task 的完整成员重新逐项复核，再保存新审核版本。前端会明确发送 `source_task_id`；仅建立新 Gate 后回到旧任务表单保存，并不会自动把数据池绑定到新数据。

CAPA 的人工批准、执行与 Child Run 保持现有独立流程。保存数据池记录不等于 Worker 已执行，也不会自动关闭 CAPA。

## 5. 把已验收版本交给训练

从当前数据池的视觉训练入口进入模型中心。服务端使用当前完整数据池与真实框生成检测数据集；页面不需要填写服务器目录，也不会由客户端编造框。

还需明确固定类别顺序、逐成员采集分组和正常空框声明。服务端要求完整 Gate PASS、当前全员合格审核版本、图片/标注版本一致，并校验 train/val/test 的采集组、字节和像素隔离。过期版本或尚未检查的派生子集不能登记为合格训练输入。

冻结数据集不会自动训练。选择可信运行环境、起始权重或随机架构、资源预算，明确授权启动。断线后读取原运行记录，不自动重开第二个训练任务。训练成功仅代表权重和验证结果产生；低分甚至零分的候选仍需如实展示并由人工决定，不批准生产上线。

## 6. 验证问题如何进入下一轮

只从开发验证集产生模型问题候选。实际误检、漏检和匹配结果绑定本次模型、数据与样本版本；它们是人工复核线索，不自动证明原标注错误。

人工区分模型错误、难样本、需要重审标签和无法判断。针对问题收集或修订**新的训练数据**，重新走标注审核、冻结、Gate、数据池与数据集流程，再把下一轮训练显式关联到已复核的问题。原验证/测试成员不复制进训练集，修复说明也不直接变成训练标签。

只有已复核且不是 `UNKNOWN` 的反馈可以被关联到视觉模型下一轮。无法判断的记录继续 HOLD，不能用补充任意数据或修改说明来绕过；当前接口不承诺可直接重写已封存的人工分类。

`/learning` 保留独立的轻量 CPU 参考学习闭环，用于验证有标签训练、候选比较、回流及一次性最终测试协议。它不是 YOLO 检测模型，也不是工业精度证明。两个训练入口的结果不能互相冒充。

参考学习周期的标签错误 `LABEL_ERROR` 或证据不足 `INSUFFICIENT_EVIDENCE` 会进入 `HOLD_REQUIRES_NEW_PROTOCOL`。此时不能只加训练数据继续原评测周期，必须重新处理评估协议与证据。

## 边界和当前限制

- 不做手机端，沿用桌面 Web / IDE 布局。
- 检测训练为有界 CPU 路线；当前合同最多 64 个样本，轮数、图像尺寸、时长和线程数有限制。大规模训练应走后续已核验算力适配器，不能宣称已支持不限规模。
- TTT / 测试时训练未作为已完成能力启用。当前是人工监督的数据迭代与再训练；不在最终测试集上调参或回灌。
- CANN / 昇腾是独立离线交接边界；没有真实调度回执就不称为 NPU 已运行。
- 本地账户、接口和源码浏览器验收，不等同于新 Windows 安装包验收。旧安装器、干净机器安装、企业 IAM、真实客户精度与生产放行分别核验。
- 请求超时不等于未写入。数据池和视觉训练使用原请求标识进行显式 GET 对账；未确认前禁止自动重复 POST。

本流程的价值在于每轮有可追溯输入、明确授权、可检查输出和失败处理，不在于保证每一轮模型指标都会提高。

## 为什么这轮没有把监督续训命名为 TTT

核对的原始资料：

- [Sun 等，ICML 2020：Test-Time Training with Self-Supervision](https://proceedings.mlr.press/v119/sun20b.html)：把未标注测试样本转成自监督任务，并在预测前更新参数。
- [Wang 等，ICLR 2021：Tent](https://arxiv.org/abs/2006.10726)：通过测试输入预测熵优化部分模型参数，不依赖人工纠正后的训练标签。
- [Ultralytics YOLO26 官方模型说明](https://docs.ultralytics.com/models/yolo26/)：检测与分割是独立的任务/权重选择，官方预训练权重也不等于本机已经下载或登记。

本轮实现的是显式标注、人审返修、新训练数据、独立验证和授权续轮。将来若研究测试时适应，需要另设与评估集隔离的适应流、可信基线、资源预算和回滚比较；不能直接在现有最终测试集上启用在线更新，再拿相同测试集证明提高。
