## 内容边界

| 内容 | 默认处理 | 使用或分发前检查 |
| --- | --- | --- |
| 自有核心代码、CLI、SDK | Apache-2.0；个别文件另有声明时以适用条款为准 | 保留许可证、适用署名并标明修改 |
| 自有 Skill 文本、Schema、规则包、文档和示例 | 无单独声明时沿用项目许可证 | 改编后说明来源、合同变化和自身修改 |
| 项目生成的合成样本与自有界面截图 | 结合项目声明和素材来源记录 | 不把合成素材当真实客户数据；上游素材另行处理 |
| Python/npm/Cargo/Maven/JRE 等依赖 | 各自许可证，不由 Apache-2.0 重新许可 | 按实际分发内容保留 notices、许可证和其他必要材料 |
| 外部模型、权重和训练环境 | 各自许可与获取渠道条款 | 软件、权重、托管、使用和再分发条件分别核查 |
| 客户数据、受限数据集、私有回执 | 不因源码许可获得使用或再分发权 | 数据所有者授权、保密、个人信息和原许可限制 |

Apache-2.0 在遵守条件时允许使用、修改、再分发和商业使用，并不要求全部衍生代码开源。分发时应提供许可证副本、显著标注修改、保留适用版权/专利/商标/署名，并保留适用 NOTICE 内容。具体条款见 [Apache 官方文本](https://www.apache.org/licenses/LICENSE-2.0)。

`production_release_allowed=false` 是产品安全行为和当前验收边界，不是在 Apache-2.0 上追加用途限制。

## 外部视觉训练与桌面分发

Torch、Ultralytics 和权重不随当前核心安装包分发；模型中心的注册记录不是许可授权书。Ultralytics 的 AGPL-3.0 / Enterprise 选择应按具体集成与分发方式核查；独立进程不自动豁免许可义务。

源码环境通过包管理器取得依赖，桌面包可能实际内嵌 Python、Java/JRE、前端和原生组件。二进制分发必须按安装器真实内容复核，不能以“源码仓没有 vendor”替代。

相关入口：[SBOM](SBOM.cdx.json) · [第三方声明](THIRD_PARTY_NOTICES.md) · [Python 许可明细](THIRD_PARTY_LICENSE_INVENTORY.generated.md) · [Cargo 快照](CARGO_LICENSES.locked.json) · [发布准备](RELEASE_PREPARATION.md)。现有 SBOM 的覆盖范围不自动等于完整桌面安装器合规认证。

## 访问与贡献

仓库访问权限与源码许可证是两个问题：Private 仓库需要授权访问，不能宣传匿名用户已可克隆；权限变化也不自动改变已合法取得版本的许可。完整 Git 历史公开还需独立隐私核验。

只提交有权贡献的内容；引入第三方代码、素材或改编时记录来源、版本、许可证和修改。贡献按 Apache-2.0 第 5 节及有效单独协议处理；本项目当前不新增 CLA、强制 DCO 或商业许可证。
