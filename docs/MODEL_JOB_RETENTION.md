# 模型任务存储与失败处理

## 当前行为

有界 CPU YOLO 训练在复制数据和启动运行环境前检查目标卷可用空间：训练／验证
文件副本、可选初始权重副本，加 576 MiB 检查点与工作空间余量。不足时记录
`YOLO_OUTPUT_SPACE_INSUFFICIENT` 并停止，不自动删除历史任务或源数据。

这是启动前检查，不是磁盘配额；它不能防止其他进程随后耗尽磁盘，也不承诺
训练的最大磁盘占用。Normality 和其他执行分支不会因该检查自动获得相同保证。

正常结束、取消、超时以及由执行器正常返回的失败结果同时产生 `result.json`
和 `retention.json`。进程崩溃或底层写盘失败仍可能无法写出这些文件；缺失结果
不得解释为成功。

## 保留与可复核清理范围

- 保留任务身份、配置、授权／请求、数据摘要、执行结果和故障日志；它们可能
  含本地路径或私域内容，仅在本地受控保存，不随公开包分发。
- `dataset`、`initial.pt`、`environment`、`probe` 是待审查的工作副本，不代表
  可以直接删除。
- 检查点可能被模型登记、选模、反馈或后续训练引用；无论任务成功与否，都需
  先检查引用关系。
- 源数据、数据池版本、登记模型、审批记录与审计链不属于临时缓存。
- 用户要求清理时，应先列出具体任务及绝对路径，确认任务已终止、无活动进程
  和引用，备份必要证据，再单独确认清理。不得宽泛递归清空 `output` 或产品目录。

当前未实现统一磁盘配额、定时清理、跨模型分支保留期限或“一键清理中心”。
保留失败目录是可审计性选择，不代表这些存储治理能力已经完成。
