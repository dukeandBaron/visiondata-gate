# 单次自监督适应与人工反馈

此路径针对已批准的 Normality 多尺度特征重建模型，不改变 YOLO detect 监督训练合同。TTT 是推理时的真实参数更新；不是换阈值、重复推理、普通离线重训练或强化学习。

## 数据怎样流动

已登记模型包与运行时 → 具名沙箱批准 → 冻结图像资产 → 明确分配用途 → 独立授权 TTT → 原模型检查与适应 → 参考组复验 → 当前图像采用候选或回滚 → 热图与回执 → 具名反馈保存、回读。

用户不必给当前待判定图像提供缺陷标签。三个集合职责不同：

| 集合 | 输入与用途 | 不允许的事 |
| --- | --- | --- |
| 当前适应批次 | 当前待推理图像必须参与；可再加 0–7 张无标签图像 | 不把预测分数或文件名当作真值标签 |
| 正常旧参考 | 1–8 张由操作者明确确认的正常参考，保持冻结教师行为 | 不使用验证/测试标签反传训练；正常声明不是系统自动认证 |
| 独立复验组 | 2–16 张正常/异常参考，必须同时包含两类；只计算复验指标 | 不参与梯度、调阈值或每步选择最优 checkpoint |

各组按文件 SHA 与实际解码 RGB 像素/尺寸同时排重。相同图像换一种压缩不能绕过隔离。它不证明近重复图像或同一物理工件的统计独立性，真实现场还需要批次/工件分组设计。

## 参数和损失

主干网络、正常分布归一化器、图像阈值和像素阈值全部固定；仅复制并更新各尺度 student 重建模块。当前实现为 CPU SGD：

```text
总损失 = 遮蔽特征重建损失 + 冻结教师回放损失 + 0.1 × 参数锚定损失
```

- 按固定 seed 遮蔽 25% 特征元素，用原始冻结特征作为自监督重建目标。
- 正常旧参考的 teacher 输出固定，约束 student 不偏离已有行为。
- 参数锚定约束候选相对父 student 的变化；梯度范数裁剪为 1。
- 1–8 步、学习率 0.00001–0.01、适应预算 5–120 秒；外部 worker 总预算另设上限 300 秒。
- 记录实际损失、梯度、步数、父/候选/实际采用的参数 SHA，不能由客户端填写这些测量值。

这是 **单次、非持久化适应**：每次从同一冻结父模型开始。候选最多用于当前图像的推理，不覆盖父模型、不登记为永久生产模型，下次任务不会继承它。由此避免把一次在线适应永久写进全局权重，但不能声称对所有旧物件都没有退化。

## 什么时候采用，什么时候回滚

独立 guard 在更新前和候选完成后各评估一次，保留固定分母的 TP/TN/FP/FN。

1. 基线至少识别出一个正常参考与一个异常参考，否则更新前拒绝，原因 `TTT_GUARD_BASELINE_UNQUALIFIED`。
2. 候选的 FP 或 FN 不得增加，TP/TN 也不得归零。
3. 必须有有限的真实梯度与实际参数变化。`loss_curve` 记录每步更新前的损失；另用同一遮蔽、教师和锚点重新计算最终目标，只有 `objective_after < objective_before` 才可能采用。不能把最后一步更新前的值冒充最终候选损失。
4. 失败时采用父模型结果，记录候选尝试值和实际采用值；父模型和阈值不得改变。

这只是小参考组的最低工程检查，不是工业验收阈值，也不是总体准确率、召回率或防遗忘保证。一次候选被采用同样不证明业务收益。

硬超时或 worker 崩溃时，无法可靠知道完成了多少步，服务保存 `FAILED_CLOSED` 独立失败回执，测量不可用，不伪造 0 步或分数。原 request_key 可只读对账，不自动重跑；新执行必须再次授权。存储系统不可用时仍报 HOLD，不承诺不存在的审计记录。

## 工作台操作

在模型中心的 Normality 页面先登记、核验模型与运行时，再登记输入资产。程序升级使旧批准失效时，使用“重新核验沙箱批准”，而不是清掉错误继续运行。打开 TTT 能力检查后，选择当前图像、正常旧参考和正常/异常复验图像，确认各项授权，再执行一次。

页面展示真实 PNG 热图；浏览器校验字节摘要、响应头、长度和尺寸后才创建预览。账号、项目或记录变化会取消旧读取并撤销图像 URL。人工反馈经 POST 保存并 GET 回读才显示完成；它不是标签真值，不会自动训练、创建 CAPA、关闭责任或放行生产。

### 反馈怎样转成真正的待办

对于标签复核或疑似误报反馈，先独立授权“导入工作簿”：服务器从已绑定的图像内容库读取原图，创建真实工作簿资产，保留模型、推理、反馈和图像摘要；此时没有标注，也没有工单。非标准 EXIF 方向先拒绝，需产生规范化新资产并重新推理，不能静默改变标注坐标系。

随后在工作簿中由人框选、保存，再回到反馈页读取实际标注版本，选择框和负责人，显式创建 OPEN 工单。服务器验证标注来源、版本、图像和裁剪摘要；重复请求按同键返回同一对象。跨数据库/文件存储中断时保留意图，仅 GET 核对已存在对象，不自动再次导入或派单。工单后续状态变化会触发重新核对，不覆写最初的 OPEN 绑定回执。

这是“模型信号 → 人审材料 → 实际待办”的桥接，不是自动标注、缺陷真值、责任关闭或训练摄入。正常反馈记录不会被修改成已经完成工单；后续对象有独立的关联回执。

## 开放接口

- `GET /v1/projects/{project_id}/vision-ttt-capabilities`
- `POST /v1/projects/{project_id}/vision-models/{model_id}/ttt-inferences`
- `GET /v1/projects/{project_id}/vision-ttt-failures`
- `GET /v1/projects/{project_id}/vision-inferences/{inference_id}/heatmap`
- `GET / POST /v1/projects/{project_id}/vision-inferences/{inference_id}/feedback`
- 既有 `vision-operations/{operation}/{request_key}` 用于精确请求对账。
- `POST normality-feedback/{feedback_id}/followup-import`：创建待人工标注资产。
- `POST normality-feedback/{feedback_id}/followup-work-orders`：基于已保存人工框创建真实 OPEN 工单。
- `GET normality-feedback/{feedback_id}/followup` 与 `normality-followup-operations/{operation}/{request_key}`：查血缘和中断对账。

TTT、热图、反馈与失败均受账号/项目权限约束。操作前后复核模型批准、运行时、输入和实现身份；请求、回执、参数、图像与 PNG 分别绑定摘要。应用进程不导入 Torch，由已明确登记的外部解释器执行；进程边界并不是针对恶意原生代码的操作系统沙箱。

实现：[算法](../src/visiondata_gate/normality_ttt.py)、[服务与验证](../src/visiondata_gate/normality_adaptation_service.py)、[API](../src/visiondata_gate/normality_adaptation_api.py)、[请求 Schema](../schemas/normality_ttt_requests.v1.json)。

## 复现与声明边界

使用自行核验的现有 Torch CPU 环境运行：

```text
python tools/run_normality_ttt_synthetic.py
python -m pytest tests/test_normality_ttt.py tests/test_normality_inference.py -q
```

合成脚本覆盖真实梯度正例、参考异常退化回滚、全漏检/全误报基线拒绝、同 seed 重现与隔离 worker 启动。无 Torch 环境会跳过真实 tensor 测试，跳过不是通过。

完整 Normality 执行另需合法的 YOLO26 v2 模型包、外部 Torch/Torchvision/Ultralytics 环境及明确授权；不自动下载权重。真实 pack 的执行记录、合成机制证据、接口替身测试和工厂效果分别报告。TTT 不等于永久持续学习，RL、自动语义标注和自动生产放行不因本功能存在而得到实现声明。
