# Claim scope

This is the public claim boundary for the current source update, not a copy of internal pilot reports or a release verdict.

## Definitions

| Claim | What supports it | What it does not imply |
|---|---|---|
| Local-first | Loopback services, local project/artifact storage and explicit provider configuration | Offline dependency installation, a certified air gap or a full-machine network audit |
| Agent workflow | Persisted task/plan/evidence, worker selection and bounded tool execution | Unrestricted autonomous execution or a staged dialogue proving reasoning |
| Governed data pool | Current per-member review bound to frozen findings and version identities | Independent label truth or automatic ingestion permission |
| Training loop | Explicit dataset/runtime/weights, actual run records, validation feedback and human next-round authorization | Higher accuracy, production deployment or automatic correction |
| Tamper-evident records | SHA-256 identities, JCS and linked version/receipt checks | Digital signature, trusted timestamp, legal identity attestation or immutable physical storage |
| Public source | Reviewed application and build source can be inspected and developed locally | Every dependency bundled, every test rerun, public API hosting or installed GUI qualification |
| Lightweight | A bounded local CPU route and optional external model runtime | A measured advantage over every alternative or unrestricted model scale |

## Measured protocols stay separate

**DynamicBench-v3** uses eight frozen synthetic scenarios and two orchestration strategies. The dynamic strategy obtains 8/8 correct terminal states and the fixed strategy 4/8; both have 0/8 unsafe releases. Tool calls are 14 versus 24. Fixed-strategy errors are conservative HOLD outcomes. External model calls are zero. These results describe this protocol only.

The public VisA governance proxy has 600 source-bound episodes, with 525/600 correct terminal states for both compared strategies. The reported difference is 150 avoided non-retryable retries, not higher detection accuracy. Raw inputs and source bindings are not redistributed.

The two-round synthetic CPU detection smoke is a distinct engineering example. Both rounds have mAP 0 and the second candidate is rejected. Do not describe a completed training run as a gain or merge this denominator with benchmark episodes.

Published reports and limitations: [Benchmarks](../benchmarks/README.md). The presence of source/tools does not independently revalidate previously reported numbers.

## Explicit non-claims

```text
production_release_allowed=false
production_decision_authority=human_only
machine_write_permitted=false
factory_metrics=NOT_MEASURED_PENDING_ADJUDICATION
industrial_effectiveness_status=NOT_EVALUATED
compute_handoff=PREPARED_NOT_SUBMITTED
```

- No demonstrated customer contract, ROI, labor saving, plant NG-rate improvement or professional field acceptance is claimed.
- No private dataset is licensed for broader use merely because a past local test exists.
- Local API LIVE is not a factory online connection; REPLAY and OFFLINE_EXPORT are not current runtime evidence.
- CANN job preparation is not actual scheduling, NPU execution or a hardware-performance claim.
- The current visual route is bounded CPU detect, not GPU training, segmentation training, test-time training or test-set adaptation.
- Registered weights are not loaded weights; random architecture initialization is not a pretrained model.
- Registration approval is not project membership; a local account system is not SSO/MFA or enterprise IAM certification.
- No installer generation, installation, signing, same-version upgrade or clean-machine result follows from source compilation alone.
- Existing Python/npm/Cargo dependency lists do not establish a complete gateway/JRE/Windows-runtime SBOM.

## Failure is a valid result

Do not replace missing evidence with synthetic fixtures, a previous PASS or invented confidence. Stale reads must be labeled stale; unresolved findings remain HOLD. Unknown write outcomes require explicit read reconciliation, not automatic resubmission.

A full training pipeline can legitimately reject its output. A remediation run can legitimately stay open. Closing a software workflow is not proof of resolving the original industrial issue.
