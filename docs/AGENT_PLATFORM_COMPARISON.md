## 本轮五项具体改进

1. **任务执行归属与恢复。** 每次新任务执行持有同机文件锁，并在 SQLite 中记录托管归属。进程退出后锁由 OS 释放；只有有托管存证且已无执行者的 RUNNING/VERIFYING 任务可由具名人员确认恢复。原尝试保留，新任务必须重新审批。这是显式重试，不是 LangGraph 式从任意 checkpoint 继续，也不是多机租约调度。
2. **模型用量核算。** 验证任务和案件回执后，分别展示逻辑调用、HTTP 尝试、供应商报告的 Token、估算和未报告项。回放不算远端调用；重试成功的最后一次响应不代表全部尝试的账单。未配置价格时费用保持未知。
3. **能力目录。** API 读取当前代码注册的工具、当前操作者的工作空间模型配置和最多 200 项任务。注册不等于某任务已调用，配置不等于已连接。该接口不会发起网络探测或模型调用。
4. **统一平台页面。** 本地 `/platform` 提供按项目选任务、读取调用量、核验执行归属、具名提交恢复和打开待审批替代任务。前端校验 scope、正文摘要与响应头；公开只读页面不打包私域平台模块。
5. **离线备份和恢复。** 将 ProductRoot 内的数据库与文件复制到独立目录，校验来源前后、副本文件集合与摘要，并只允许恢复到不存在的新目录。备份含私域数据，不是公开发布包。

## 仍存在的主要差距

- **部署与团队使用：** 当前以本机 Windows、SQLite 和本地会话为主；没有完成生产 SSO/OIDC、细粒度团队角色、PostgreSQL、多实例部署和跨机执行。
- **恢复能力：** 新增的是显式中断重试。历史未知运行不会自动接管；没有自动定时重试、跨工具 checkpoint 或后台调度服务。
- **观测与预算：** 当前是保存回执的任务级核算，不包含完整 OpenTelemetry 管道、提供商账户账单对账、跨项目周/月汇总或货币预算强制执行。
- **模型接入：** 已有可替换 Planner 合同；StepFun 等提供方仍需实际适配、授权配置和调用验证。模型配置不能当作真实调用证明。
- **工业效果：** 合成用例、私域离线数据和工厂影子验证需要分别报告；尚缺的外部真值、客户反馈与实际生产指标不会因平台功能增加而自动补齐。
- **开源体验：** 发布包、文档导航、跨平台安装验证和稳定版本说明仍需持续整理。本轮不会把本地工作树通过写成 GitHub 已发布。

项目继续聚焦“工业视觉数据门禁与整改复验”。优先完成这段业务的可靠性与可观测性，再扩大平台范围，比直接更换名称更能体现产品成熟度。
